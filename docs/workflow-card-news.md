# 워크플로 안의 뉴스 수집·카드 생성 노드

진입점은 기존 **새로 만들기 → 워크플로**다.

- 이름: `주식 카드뉴스 인스타 업로드`
- 한 줄 설명: `정해진 시간마다 국내주식 뉴스를 스크랩해서 카드뉴스를 생성한후 인스타에 업로드하는 것을 돕습니다.`

설명으로 자동 구성을 선택하면 다음 그래프를 만든다.

`예약 → 주식 뉴스 수집 → 기존 LLM 정보 추출 → 카드뉴스 생성 → 승인 → 결과 반환`

별도 사이드바 메뉴, 카드뉴스 페이지, 최신 뉴스 대시보드와 전역 수집 API/작업은 없다.
이전에 잘못 추가했던 `/stock-news` 화면과 전역 수집 구성은 제거했다.

## 노드 설정

- 예약: `0 7 * * *`, `Asia/Seoul`. 실제 자동 실행은 서버의 워크플로 스케줄러를 별도로 연결해야 한다.
- 뉴스 수집: 공개 증권 RSS와 공개 기사 설명문을 읽어 `articles` 배열로 전달한다.
- 기존 LLM: 모델/키/프롬프트를 기존 설정 패널에서 지정한다. 참고 자료에 기사 배열을 연결한다.
  `{articles:[{article_id,title,summary},...]}` 형식으로 국내 기사 4건을 선정·요약한다.
- 카드 생성: LLM JSON과 수집 원문을 각각 연결한다. 표지 제목·인스타 계정명을 노드에서 지정한다.
  요약 ID와 실제 수집 원문을 대조하고 표지 1장 + 기사 4장, 게시 문안을 만든다.
- 승인: 편집기 실행 콘솔의 **카드뉴스** 탭에서 5장과 출처를 확인한 뒤 승인한다.
- 인스타그램 실제 게시 노드는 아직 미구현이다. 승인해도 외부에 게시하지 않는다.

## 결과 확인

편집기의 테스트 실행 후 하단 **카드뉴스** 탭에 이 실행의 카드 생성 노드 출력만 표시한다.
각 이미지를 크게 보거나 1080×1350 JPEG로 내려받는다. 별도 화면으로 이동하지 않는다.
실제 백엔드는 노드 입력·출력을 기존 실행 단계 JSON에 보관한다.

목 API에서는 `[샘플]`로 명시한 데이터로 노드 연결·이미지 배치를 확인한다.
실제 기사와 LLM은 실제 백엔드 모드에서 실행해야 한다. 모델 키가 없을 때 실제 기사 요약을 가짜 응답으로 대체하지 않는다.

## Git과 검증

프론트와 백엔드는 각 `feat/stock-news-card-generation` 브랜치에 있다.
백엔드는 기존 실행 폴더를 보존하기 위해 `tmp/moa-backend-stock-news` worktree에서 수정했다.
이 폴더를 프론트 PR에 추가하지 않는다. push·PR은 사용자가 직접 진행한다.

사용자의 실제 이름·설명으로 생성 → 편집기 노드 설정 → 테스트 실행 → 카드 5장 확인·다운로드를 검증한다.
새로 추가한 노드/결과 UI만 기존 MOA 편집기의 디자인 토큰에 맞췄다.
