# Claude Code 프롬프트 모음 — 목 API로 프론트 완성까지

## 사용법
- `moa-web` 폴더에서 `claude`를 실행해야 CLAUDE.md가 읽힌다.
- **방법 A (권장)**: 단계별 프롬프트를 순서대로 쓴다. 단계마다 `/clear`로 새로 시작하고, 끝나면 직접 화면을 확인한 뒤 다음 단계로 간다.
- **방법 B**: 맨 아래 "한 번에 지시" 프롬프트 하나로 끝까지 맡긴다. 빠르지만 중간에 방향을 틀기 어렵다. 쓰더라도 0단계 결과(피그마 추출·계획)는 꼭 사람이 보고 넘어간다.
- 목 데이터는 **메모리에만** 둔다. 화면 이동 중에는 유지되고, 새로고침하면 시드 데이터로 돌아간다.

## 공통 문장
모든 화면 프롬프트 끝에 아래 문장을 붙인다.

```
기준: docs/figma/<화면>.md·.png, docs/design.md의 관련 절.
src/entities 훅만 사용하고, 로딩(skeleton)·빈 상태·오류 상태(재시도 버튼)를 모두 넣어.
키보드만으로 조작 가능해야 하고 아이콘 버튼엔 aria-label을 달아.
끝나면 pnpm dev로 띄워 Playwright 스크린샷을 찍고 피그마 저장본과 비교한 차이 목록을 보고해.
typecheck·lint·test 통과 후 feat/<이슈번호>-<이름> 브랜치에 커밋해.
```

## 2단계 — 타입과 목 API (가장 중요)

```
design.md 1.4.3 레코드 레이아웃, 2.5 DDL, 2.6 API 상세, 1.5.2 SSE, 3.3 오류 형식을 기준으로 만들어.

1) 타입·훅: src/entities/{workspace,user,agent,workflow,run,context,endpoint,api-key,template,product,license,mcp,credential,budget,usage}
   - zod 스키마(snake_case 원형) + UI용 변환 함수
   - TanStack Query 훅: 목록(커서 페이지네이션)·상세·생성·수정·삭제, query key 규칙은 CONTRIBUTING 7절
   - 수정 훅은 낙관적 업데이트 + 실패 시 롤백

2) 목 DB: src/mocks/db.ts에 메모리 저장소를 만들어(@mswjs/data 또는 Map 기반).
   - 생성·수정·삭제가 실제로 목록에 반영돼야 해. 저장은 메모리만(localStorage 쓰지 마), 새로고침하면 시드로 초기화.
   - 응답 지연은 150~500ms 랜덤, 개발 중 확인용으로 ?mock_error=<코드> 쿼리를 붙이면 해당 Problem Details 오류를 돌려줘.

3) 핸들러: design.md 2.6.2 엔드포인트 목록 전부. 필드명은 문서 그대로 snake_case.
   - 인증: 아무 이메일/비밀번호로 로그인 성공. /auth/me는 기본으로 데모 사용자를 돌려줘서 새로고침해도 로그인 상태 유지(로그아웃하면 그 페이지 세션 동안만 로그아웃).
   - 권한: 데모 사용자는 owner. 워크스페이스 스위처로 viewer 권한 워크스페이스도 하나 만들어 권한 없는 버튼이 비활성인지 확인할 수 있게.
   - 초안 저장: draft_version으로 If-Match 검사, 불일치 시 409 MOA-CTX-003 대신 워크플로용 409 반환.
   - 검증: POST /workflows/{id}/validate는 순환·미연결 필수 입력·시작 노드 없음을 실제로 검사해 issues 반환.
   - 배포: slug 중복 시 409 MOA-API-001, API 키 발급 응답에만 평문 키 포함.
   - 마켓: 구매 시 clone이면 스튜디오에 복제본 에이전트·워크플로 생성, api_sub면 라이선스만 생성.

4) 실행 시뮬레이터: POST /runs 하면 run을 만들고, /runs/{id}/events SSE를 ReadableStream으로 흘려.
   - 워크플로 노드를 위상 순서대로: step.started → step.delta(LLM 노드는 글자 단위 토큰 30~80개) → step.finished
   - context.changed로 토큰 사용량 증가, 70%를 넘으면 compressed=true 이벤트
   - 입력 텍스트에 "fail"이 있으면 중간 노드 실패, 승인 노드가 있으면 approval.required 후 waiting_approval로 멈춤
   - POST /approvals/{id}/decision 하면 이어서 진행, POST /runs/{id}/cancel 하면 canceled
   - 3D 노드는 결과로 공개 샘플 glb URL과 미리보기 이미지를 돌려줘
   - 15초마다 heartbeat

5) 시드 데이터(src/mocks/fixtures, 한국어로 그럴듯하게):
   - 워크스페이스 2(owner 1, viewer 1), 멤버 4
   - 에이전트 6, 워크플로 8(각 노드 4~10개, 조건 분기·승인·3D 노드 포함 예시 1개씩)
   - 실행 이력 30(성공·실패·승인 대기·취소 섞어서), 컨텍스트 블록 포함
   - 템플릿 24개(8개 카테고리: 콘텐츠, 리서치, 고객지원, 데이터, 개발, 마케팅, 3D·디자인, 업무자동화)
   - 노드 팔레트 8그룹 47블록(입력·출력, LLM, 도구·MCP, 로직, 데이터, 지식, 3D, 사람·승인)
   - 마켓 상품 12(리뷰·버전 포함), 엔드포인트 3, API 키 2, MCP 서버 3(도구 각 3~6개), 자격증명 3, 예산·30일 사용량

6) 테스트: 핸들러별 Vitest(정상·오류), 실행 시뮬레이터 이벤트 순서 테스트.
커밋해.
```

## 3단계 — 화면 구현

아래 순서대로 하나씩 진행한다. 각 프롬프트 끝에 **공통 문장**을 붙인다.

### 3-1. 로그인 · 회원가입
```
/login, /signup 화면을 구현해.
이메일·비밀번호 폼(zod 검증, 오류 문구), Google·GitHub 소셜 버튼(목: 바로 로그인),
로그인 후 원래 가려던 페이지로 이동(redirect 파라미터), 비로그인 상태로 (app) 라우트 접근 시 /login으로.
```

### 3-2. 홈 대시보드
```
/home을 구현해.
인사말 + 빠른 시작(새 에이전트, 템플릿으로 시작, 워크플로 만들기),
최근 에이전트 카드 4개, 최근 실행 5건(상태 배지, 클릭 시 실행 상세),
승인 대기 목록(바로 승인/거부), 이번 달 사용량 요약(비용·토큰·실행 수, 예산 대비 게이지),
추천 템플릿 3개.
```

### 3-3. 스튜디오
```
/studio를 구현해. 탭: 에이전트 / 워크플로 (searchParams ?tab=).
검색, 정렬(최근 수정·이름·실행 수), 필터(배포 여부), 카드/리스트 보기 전환,
카드 메뉴: 열기, 복제, 이름 변경, 삭제(확인 다이얼로그, viewer는 비활성),
"새로 만들기" 드롭다운(빈 에이전트, 빈 워크플로, 템플릿에서), 커서 기반 무한 스크롤, 빈 상태 안내.
```

### 3-4. 템플릿 갤러리
```
/templates를 구현해.
카테고리 8개 탭/칩, 검색, 템플릿 카드(아이콘, 이름, 한 줄 설명, 사용 노드 수, 난이도),
카드 클릭 시 상세 시트: 설명, 워크플로 미리보기(React Flow 읽기 전용 축소판), 필요한 연결(자격증명·MCP) 체크리스트,
"이 템플릿으로 시작" → 복제 생성 후 에이전트 빌더로 이동, 필요한 연결이 빠져 있으면 안내 배너.
```

### 3-5. 에이전트 빌더
```
/agents/new, /agents/[id]를 구현해. 좌측 설정, 우측 테스트 채팅 패널.
설정 섹션:
- 기본 정보(이름, 설명, 아이콘)
- 모델(드롭다운 + 폴백 모델 다중 선택, temperature 슬라이더)
- 시스템 프롬프트(글자 수·추정 토큰 표시)
- 스킬: "스킬 추가" 다이얼로그에서 MCP 서버별 도구·내장 스킬 검색·선택, 각 스킬의 "실행 전 승인" 스위치(destructive 도구는 기본 켜짐)
- 워크플로 연결: 기존 워크플로 선택 또는 새로 만들기, 별칭(alias) 입력, 편집기로 열기
- 메모리 사용 스위치
저장은 명시적 저장 버튼 + 이탈 경고.
테스트 패널: 메시지 입력 → POST /runs 후 SSE로 답변 스트리밍, 도구 호출을 접이식 카드로 표시, 대화 초기화.
상단에 "배포" 버튼(배포 화면으로 이동).
```

### 3-6. 워크플로 편집기 (5번에 나눠서)
매번 프롬프트에 "design.md 3.4.3의 스토어 구조와 자동 저장 의사코드를 그대로 따라"를 붙인다.

**① 캔버스·노드 팔레트**
```
/workflows/[id]/edit의 캔버스를 구현해(@xyflow/react, Zustand 스토어).
좌측 노드 팔레트: 8그룹 47블록, 검색, 드래그로 캔버스에 추가.
노드: 타입별 색(shared/ui/node-colors.ts)·아이콘·제목·입출력 포트, 포트 타입이 안 맞으면 연결 불가 표시.
연결·삭제(Delete), 다중 선택, 복사/붙여넣기, 실행 취소/다시 실행(⌘Z/⇧⌘Z, zundo), 미니맵, 줌 컨트롤, 자동 정렬 버튼.
```

**② 노드 인스펙터**
```
우측 인스펙터를 구현해. 선택한 노드 타입별 설정 폼:
LLM(모델, 프롬프트 템플릿 + {{노드.output.필드}} 자동완성, 폴백, 재시도·타임아웃),
도구/MCP(도구 선택 → 입력 스키마로 폼 자동 생성), 조건(분기 규칙), HTTP(메서드·URL·헤더),
지식검색(KB·top-k), 코드, 3D(모드·해상도), 승인(승인자·요약 문구), 입력(입력 필드 스키마 정의 → 배포 시 API 스키마가 됨).
POST /validate 결과 오류를 노드 빨간 테두리 + 인스펙터 상단 목록으로 표시, 클릭 시 해당 노드로 이동.
```

**③ 자동 저장·충돌 처리**
```
자동 저장을 구현해: 변경 후 1.5초 디바운스로 PUT /draft(If-Match: draft_version).
상단에 저장 상태 표시(저장 중/저장됨/오류 + 재시도), 이탈 경고(beforeunload, 라우트 이동).
409면 충돌 다이얼로그: 내 변경과 서버 최신본 비교 요약, "내 것으로 덮어쓰기"/"서버 것 불러오기".
"버전 저장" 버튼(POST /versions, 메모 입력), 버전 목록 시트에서 이전 버전 보기(읽기 전용).
```

**④ 실행 콘솔·SSE**
```
하단 실행 콘솔을 구현해. "테스트 실행" → 입력 노드 스키마로 만든 입력 폼 다이얼로그 → POST /runs → SSE 구독.
노드 상태를 캔버스에 실시간 반영(대기/실행 중 애니메이션/성공/실패), 콘솔 탭: 로그(step.delta 스트리밍, 가상 스크롤), 노드별 입출력, 토큰·비용 합계.
approval.required면 콘솔과 노드에 승인/거부 버튼, 실행 취소 버튼, 연결 끊김 시 재연결 배너.
```

**⑤ 컨텍스트 패널**
```
우측에 컨텍스트 탭을 추가해(인스펙터와 탭 전환).
현재 세션 블록 목록(역할 배지, 토큰 수, 미리보기), 블록별 고정·끄기·우선순위 변경(PATCH + If-Match),
상단 토큰 게이지(예산 대비, 70% 지점 표시), 압축이 일어나면 요약 블록과 "원문 펼치기",
스냅샷 저장·복원.
```

### 3-7. 실행 목록 · 실행 상세
```
/runs와 /runs/[id]를 구현해.
목록: 상태·트리거·에이전트 필터, 기간 선택, 표(상태, 에이전트, 트리거, 소요 시간, 토큰, 비용, 시작 시각), 커서 페이지네이션.
상세: 상단 요약(상태, 소요 시간, 비용, 재실행 버튼),
좌측 노드 타임라인(간트 형태, 노드별 시도 횟수·폴백 모델 배지), 우측 선택 노드의 입력·출력(JSON 뷰어, 복사), 오류면 오류 코드와 설명,
3D 노드 출력은 three.js 뷰어(@react-three/fiber, next/dynamic ssr:false, 회전·확대, glb 다운로드),
진행 중이면 SSE로 실시간 갱신, 승인 대기면 승인 카드.
```

### 3-8. 배포 · API 키
```
/deploy와 /deploy/[endpointId]를 구현해.
목록: 엔드포인트 표(slug, 에이전트, 모드, 호출 수, 상태 스위치).
새 배포 다이얼로그: 에이전트 선택, slug 입력(형식·중복 실시간 검사), 동기/비동기, 웹훅 URL, 분당 한도.
상세 탭:
- 개요(엔드포인트 URL 복사, 최근 7일 호출 차트)
- 호출 예시(curl·JavaScript·Python 탭, 입력 스키마로 예시 본문 자동 생성)
- OpenAPI(JSON 보기·다운로드)
- 플레이그라운드(폼으로 호출해 응답 확인)
- 웹훅(서명 비밀 보기, 최근 전송 기록·재전송)
API 키: 설정 > API 키에서 발급(평문은 발급 직후 한 번만 보여주고 복사 버튼, 닫으면 다시 못 봄), 이름·만료일·마지막 사용, 폐기.
```

### 3-9. 마켓
```
/market, /market/[id], /market/sell, /market/purchases를 구현해.
목록: 검색, 카테고리, 정렬(인기·평점·최신·가격), 상품 카드(평점, 설치 수, 가격, 라이선스 배지).
상세: README(마크다운 렌더), 스크린샷, 버전 기록, 리뷰(별점 분포 + 목록), 판매자 정보,
라이선스 선택(복제 1회 구매 / API 월 구독) → 모의 결제 다이얼로그 → 완료 화면(복제면 "스튜디오에서 열기", 구독이면 호출 정보).
판매 등록: 내 에이전트 선택 → 정보 입력(제목, 요약, 카테고리, 태그, 가격, 라이선스 종류, README) →
보안 검사 결과(자격증명 자동 제거 info, 비밀값 의심 error면 등록 막고 위치 표시) → 제출.
구매 내역: 라이선스 목록, 만료일, 리뷰 작성.
```

## 4단계 — 통합 E2E

```
다음 흐름을 Playwright E2E로 만들고 pnpm test:e2e 하나로 돌아가게 해(목 API 모드, 각 테스트는 새 페이지로 시작해 시드 상태에서 출발):
1) 로그인 → 템플릿 선택 → 편집기에서 노드 추가 → 테스트 실행 → 성공 결과 확인
2) 에이전트 생성 → 스킬·워크플로 연결 → 테스트 채팅 → 배포 → API 키 발급 → 플레이그라운드 호출
3) 승인 노드가 있는 실행 → 승인 대기 → 승인 → 완료
4) "fail" 입력 실행 → 실패 노드·오류 코드 표시 → 입력 수정 후 재실행 성공
5) 마켓 복제 라이선스 구매 → 스튜디오에 복제본 표시
6) 같은 워크플로를 두 페이지에서 편집 → 충돌 다이얼로그 → 서버 것 불러오기
7) viewer 워크스페이스로 전환 → 삭제·배포 버튼 비활성
실패하는 흐름은 원인을 고쳐서 통과시키고, 결과 요약을 보고해.
```
